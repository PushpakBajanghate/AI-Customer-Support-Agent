ℹ️ Router Node (Intent Classifier)

The Router is the first node in the LangGraph graph. It uses Google Gemini to analyze the user message and conversation history, classifying into exactly one of 13 supported intent types (e.g. ORDER_TRACKING, ORDER_CANCEL, ORDER_RETURN, HUMAN_ESCALATION). Crucially, the Router does not perform database mutations or invent data.

Input State: customer_id, message, conversation_history
Output State: intent, confidence, needs_clarification, required_info
Safety Guarantee: Read-only classification; no side effects permitted.

Architecture Talking Points for Technical Interviews

Why LangGraph instead of monolithic chains?

LangGraph establishes clear boundaries between reasoning and side-effects. The Router classifies intent without DB access. The Support Agent inspects state using read-only tools. The Supervisor node validates ownership and enforces user confirmation before invoking write tools.

How is multi-tenant security guaranteed?

Customer ID is strictly extracted from verified JWT Bearer tokens, never accepted from user chat prompts. All database tools constrain lookups by authenticated customer ID. When customer Alice asks about order #201 belonging to Bob, the system returns ORDER_NOT_FOUND without leaking Bob's existence.

Why evaluation without fine-tuning?

Enterprise business policies and catalog items change continuously. Fine-tuning models embeds brittle assumptions into model weights. Modern platforms (Decagon) keep models agile through prompt orchestration, tool gating, and deterministic state graphs, rigorously evaluated on synthetic cohorts.

How does RAG prevent transactional confusion?

RAG retrieves only unstructured policies (return windows, warranties, FAQs) from Qdrant/markdown documents. It is never used for transactional truth (order status, prices, shipments), which are queried directly from PostgreSQL through verified relational models.
